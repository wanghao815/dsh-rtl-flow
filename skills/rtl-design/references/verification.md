# 参考模型、验证与形式

先规定可观察行为、合法域和验收，再运行 DUT。测试必须从真实输出/读接口取值；不能直接把预期结果写入 DUT 存储或用内部诊断值替代外部输出。

## Reference 与输入

对控制模块建立独立的队列/事务/状态模型；对精确整数或协议通常逐 bit、顺序和周期精确比较。固定点需明确量化、饱和或回绕。浮点需明确编码、解码、scale、累加顺序、每个舍入节点、异常和 subnormal。不要让宿主库默认 FMA、归约顺序或双精度改变 golden。

输入由独立 manifest 保存参数、配置、seed、编码/布局版本和摘要；同一 manifest 能重建同一输入。打包/解包的往返还需独立已知字节检查，二者共用同一错误不能自证正确。参考模型通过不等于 DUT 通过。

允许数值容差时，先从运算图和输入推导规则。若用 `abs(R-G) <= B`，R 是 DUT 输出，G 是独立参考值，B 是不依赖 DUT 结果的绝对误差上界，abs 表示绝对值，减号表示两值之差，<= 表示误差不得超过上界。B=0 要求数值相等。域判定在观察 DUT 前完成；中间节点溢出条件也需检查。位宽、常数和预算均按当前数值路径推导。地址、顺序、有效标记和完成周期始终按合同精确检查。

域内 NaN/Inf 或协议错误直接失败，不在观察输出后改判域外。域外若合同仅保证控制，只计控制覆盖；若项目承诺 IEEE 异常语义则照常精确检查。零、下溢和抵消需严格规范例，宽容差可能放过错误清零。舍入边界的预期常数要在看到 DUT 之前推导。

## Testbench 与回归

定义驱动沿、pre 采样和 post 观察区，避免 RisingEdge 后将更新值当作本沿已接受的数据。逐项观察传输、状态更新、地址、结果顺序、完成及后续保持。固定周期的 off-by-one 必须失败，增加超时不能掩盖延迟变化。可反压协议则以真实接受事件推进 scoreboard。

| 集合 | 目的 |
| --- | --- |
| 手算 smoke | 先于大回归；算术用全 0、全 1、单一非零、单位映射和正负抵消等适用输入，协议/存储用固定短序列；列出可独立核算的中间状态与逐沿结果 |
| 边界/参数 | 最小最大配置、深度/地址 wrap、full/empty、复位/flush 和合法尾块 |
| 固定 seed 随机 | 可复现的功能组合、突发和回压；规模由风险与预算确定 |
| 规范定向 | 舍入、下溢、符号、掩码、异常、仲裁及协议特有边界 |
| 负例/故障注入 | 错地址、缺/多传输、错标签、提前完成等由指定判据检出 |
| 宏同镜像 | 相同输入文件摘要，真实宏模型接收并通过实际 bank/输出接口回读 |
| 最终回归 | 选定版本与配置下的受影响集合，不无限重复已通过测试 |

任务是否单次、可连续或并发由项目接口决定。优先复用编译产物，失败按同 seed 开启波形。至少保存一个代表性通过用例的原始 VCD/FST、可读关键边沿图和采样核查，标注测试与源摘要。图中选取输入、有效信号、关键寄存器、反馈状态、写回和完成信号，逐沿解释它们如何满足合同；这些内容是阶段交付的一部分。

## Formal 与等价

选择计数、地址、守恒、互斥、顺序、有效性、复位、完成等可证明性质。环境只约束合法协议；cover 检查非空和关键路径可达，liveness 清楚写公平性。写明算术/宏抽象及假设，不能把抽象控制证明声称成完整算术正确。

精确语义重构和综合网表适用等价；允许误差的不同算法不直接做逐 bit 等价。保留 proof、bounded、fail、timeout、unsupported 等原始状态。协议、寄存器、共享状态和宏边界在层次/ECO 后分别核对。故意功能错误应被不等价检出，工具未完成不算检出能力通过。
