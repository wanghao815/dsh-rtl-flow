# npm 发布检查单

源码仓库：[wanghao815/dsh-rtl-flow](https://github.com/wanghao815/dsh-rtl-flow)。包名为 `dsh-rtl-flow`，版本与兼容声明以待发布提交的 `package.json` 为准。每项完成必须对应实际命令、产物或公开安装结果。

## 真实设计验证

- [ ] 在实际 dsh profile 中由模型从新需求完成架构、RTL 和独立验证，记录模型标识、非秘密配置、合同、工具调用及原始报告。
- [ ] 至少一个故障负例确实被独立 oracle 检出，保存可复现输入与代表性通过波形。
- [ ] 至少一个新小设计完成 RTL-to-GDS，核对同源 GDS、网表、SDC、寄生、数据库和布线后 STA。
- [ ] 物理检查按预声明范围执行，失败、未执行和未覆盖项保留；固定 FIFO 和合成指标不替代新设计验证。
- [ ] 修复发现的问题，复验受影响范围，能力与兼容说明只描述已验证范围。

## 最终源码与候选包

- [ ] 选定最终版本和源码提交，核对 Git 改动、公开仓库状态及依赖兼容。
- [ ] 源码只包含插件、文档、示例、模板与测试；检查不夹带本地运行报告、缓存、工艺材料、主机配置或凭据。
- [ ] 在最终提交运行必要检查与测试，保存真实退出、失败和 skip。
- [ ] 从该提交执行 `npm pack`，核对文件白名单、可执行 CLI、版本与 SHA-256；不按版本号复用已有 tarball。
- [ ] 在干净测试 profile 安装候选 tarball，确认实际宿主加载、五工具、配置、资源检测和卸载。
- [ ] 对同一候选 tarball 执行 publish dry-run，保存结果。

## npm 发布与公开复验

- [ ] 重新核对 npm 登录身份、registry、包名权限与版本占用；认证和 2FA 在本机完成，不在聊天或报告中保存秘密。
- [ ] 发布 GitHub 源码，tag/release 指向候选包对应的实际提交。
- [ ] 发布已核对的同一份 tarball，记录版本、源提交、SHA-256、registry 完整性和真实发布结果。
- [ ] 从公开 registry 安装到干净 dsh profile，复验加载、五工具、资源检测及卸载，确认安装来源为公开包。

真实设计验证与最终候选核对未完成时，不执行 npm 正式发布。GitHub 源码公开供检查和试用，不能作为 npm 或真实设计验证已完成的依据。命令与安装方法见 [打包、安装和发布](publishing.md)。

## 可选市场收录

市场收录须另行提出。届时核对目录最新规则、条目格式、审核与同步要求，再提交并验证展示和安装。npm 发布不自动完成市场收录。
