## 本轮发现与修复

首次复核发现全局证据无效但关口仍显示通过、设计配置未绑定、异常字段隐式转换崩溃、物理基线仅靠标签、资源未知量和技术/归档状态混杂，已在 schema v2 分别修正并加负例。

进一步检查发现解析器可以跨检查类型误认证 STA、cocotb 只取末次汇总、任务改命令后复用旧执行记录、运行中实际 RSS 未参与设备余量判定，以及短任务磁盘漏记。本轮均修正。macOS statfs 对短写盘可能延迟更新，因此资源运行器使用卷空间和前后目录占用双测，并明确周期采样不能替代系统硬限制。

收尾的首版实现仍把失败设计任务纳入剩余执行预测，导致不能保留失败历史同时归档；已分开停止的设计项与收尾执行集合。首次文档检查另发现相对链接层级错误，修正后完整检查通过。

## 明确未覆盖

按用户决定，真实模型在 dsh 中从需求生成并验收新 IP、至少一个小设计 RTL-to-GDS 留作正式发布前执行。本轮没有调用模型 API，没有重跑来源项目后端，没有把固定 FIFO、合成指标夹具或宿主测试当作任意 RTL 生成正确性、完整 PDK 或制造签核证明。资源保护有周期采样和声明工作区的覆盖边界，需保守估算与余量。

固定宿主依赖的既有 Zod 4.4.3 风险链及 0.1.0 时的 9 个 high 依赖条目见历史验证；本轮未更换依赖或做新的漏洞扫描，不能把旧扫描数当作当前安全结论。输入长度约束不代替宿主依赖修复。

上述功能验证阶段没有公开上传，没有修改用户现有 dsh profile。后续 GitHub 源码公开与 npm 发布分别记录，当前步骤及实测条件见 [发布检查单](release-checklist.md)。
