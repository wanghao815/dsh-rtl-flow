# 验证范围与能力边界

插件测试用于验证流程工具、证据审计、资源保护和宿主集成。测试夹具与真实模型新设计验证分别记录，不能用配置示例或合成指标证明任意 IP 的正确性。

## 复验入口

在插件仓库根目录执行：

```sh
npm ci --ignore-scripts
npm run check
npm test
```

保存实际源码提交、环境、原始输出、退出码和跳过项。Node 声明为 ≥24.9；宿主 API 测试依赖固定为 DeepSeek Harness 0.2.2-rc.1、Cordis 4.1.0、Schemastery 3.19.0。其他宿主版本需单独复验，不能从安装成功推导兼容。

## 测试集合覆盖

| 范围 | 检查对象 |
| --- | --- |
| 工作入口与专题 | new/adopt/modify/eco/resume、复用与影响失效、暂停保护、特性组合和草案替换 |
| 证据绑定 | 设计配置、合同与源码摘要、物理角色清单、同版交付、路径边界和异常输入 |
| 报告解析 | cocotb、Yosys、Netgen 日志夹具；检查类型匹配、较早失败、多汇总、未知格式与原生指标判据 |
| 资源预检 | 实际设备内存与空间、累计时间、剩余任务、余量、尝试预算、摘要失效、依赖及锁 |
| 运行保护 | 本次进程树超预算、监测不可用、短任务磁盘核对、原生退出与任务状态分开保留 |
| 收尾 | 技术失败和交付结果分开、明确收尾任务、暂停与归档状态保护 |
| 宿主 | 原生执行器注册五工具、schema 与返回值、输入限制、取消、关闭、重载、卸载和只读资源检测 |
| 固定 RTL 夹具 | Verilator FIFO 的绕回、满、同时出入、反压、顺序和复位；故意破坏数据由独立 scoreboard 检出 |
| 包与指导 | 元数据、示例、模板、核心流程唯一正文和本地 Markdown 链接 |

JSON 指标分支采用明确标注的合成单元夹具，不代表真实物理实跑。Verilator 缺失时 FIFO 测试会 skip；必须保留该状态。原始运行报告、临时编译产物和主机配置不随源码或 npm 包分发。

## 独立工程验证（尚未完成）

- 真实模型在实际 dsh profile 中使用本插件，从新需求生成架构、周期合同、RTL 和独立验证，并检出故障负例。
- 至少一个新小设计完成 RTL-to-GDS，保留同源网表、约束、寄生、数据库、可读 GDS 和实际布线后 STA；其余物理检查按预声明范围保留结果与开放项。

实际 Harness 加载、真实模型新设计和 RTL-to-GDS 由使用者独立安排。单元/宿主 API 测试、源码公开和 npm 发布均不代表这些工程验证已完成。

## npm 发布验证

从最终选定源码提交重新打包，检查文件清单、SHA-256、干净 npm 目录安装、模块导入、CLI 和同一 tarball 的 dry-run；发布后从公开 registry 安装并核对真实来源及完整性。具体流程见 [发布检查单](release-checklist.md)。

## 实现限制

原始报告只解析 [证据规范](evidence.md) 列出的格式。文件摘要验证一致性，不能证明报告不可篡改或规则、器件、宏和抽象覆盖完整。资源保护依赖周期采样与声明输出工作区，存在瞬时峰值盲区，需保守预算和余量。插件不全局拦截宿主的任意终端命令，不提供制造签核保证。
